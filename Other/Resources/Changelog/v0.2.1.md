# Release notes

## Changes

- one process hosts several mcp-servers: the tool-definitions-file declares them under "mcp-servers", every one of them
  states its "url-namespace" and is reachable under "&lt;domain&gt;/&lt;url-namespace&gt;" with exactly its own tools
- every tool declares its type, which is "python", "shell" or "web-request"
- a python-tool runs in a virtual environment of its own, whose packages are declared as its requirements
- a tool of the type "web-request" requests the addresses which its declaration allows
- a tool receives the credentials which its declaration assigns to it, read from the environment of the server or from
  the file a "_FILE"-variable points at
- a client reaches an mcp-server with an access-token, which an administrator creates with the call
  "CreateAccessToken" and of which only the hash is stored
- roles decide who may use which mcp-server: a client is in the roles which "Roles.csv" states, and an mcp-server
  states the roles which may use it in "authorized-roles"
- an mcp-server which is declared with "anonymous" is usable without an access-token
- a failed tool-call is answered with the http-status-code 502, a request which may not reach an mcp-server with 401
- the example declares the mcp-servers "GeneralTools" (anonymous), "Security" and "DeveloperTools" and contains a
  research-tool for the usual sources of a developer, two tools for the changelog of a version of a nuget- respectively
  pypi-package and an optional minimal version for the tools which return the available versions
- fixed that the server did not recognize that it runs in a container, which moved all of its folders and made the
  healthcheck of the image fail
